Tester Specification

Input: the task text and the scoped handoff from the previous role, including `written_entry_ids`. The Tester's only permitted tool is `read_entry`; it does not execute code or run a test suite. It must call `read_entry` with an ID taken verbatim from `written_entry_ids` (never a guessed ID), compare the stored entry's content against the requirements in the task text, and return `{handoff, output_document: {summary, citation_list}, review_items}` with one review item per checked requirement, verdict exactly "approve" or "reject". If `written_entry_ids` is empty or the read fails, it returns a single `reject` item naming the missing entry rather than approving. Known edge case: an environment or store failure makes the result inconclusive and must be reported as a blocker, not as a pass. Observed gap: in two of three HO-02 runs the Tester made no `read_entry` call and returned no verdict, which this specification would treat as a failure.
